КАК ПРОВЕРИТЬ BACKEND:
----------------------

1. Откройте в браузере:
   http://localhost:8000/docs

2. Вы увидите Swagger UI с доступными endpoints:
   - POST /api/v1/auth/register - регистрация
   - POST /api/v1/auth/login - вход
   - POST /api/v1/auth/refresh - обновление токена
   - GET /api/v1/users/me - информация о пользователе
   - GET /api/v1/files/ - список файлов
   - POST /api/v1/files/upload - загрузка файла


ТЕСТИРОВАНИЕ РЕГИСТРАЦИИ:
-------------------------

1. Перейдите на http://localhost:3000
2. Нажмите "Create Account" или "Register"
3. Введите:
   Email: test@example.com
   Password: 123456
   Full Name: Test User
4. Нажмите Register

Или через Swagger (http://localhost:8000/docs):
1. Откройте POST /api/v1/auth/register
2. Нажмите "Try it out"
3. Введите JSON:
   {
     "email": "test@example.com",
     "password": "123456",
     "full_name": "Test User"
   }
4. Нажмите Execute


ВХОД В СИСТЕМУ:
---------------

1. На странице http://localhost:3000
2. Введите:
   Email: test@example.com
   Password: 123456
3. Нажмите Login

Вы попадете в Dashboard!


СТРУКТУРА API:
--------------

/api/v1/auth/register  - Регистрация нового пользователя
/api/v1/auth/login     - Вход (получение токенов)
/api/v1/auth/refresh   - Обновление access token
/api/v1/users/me       - Информация о текущем пользователе
/api/v1/files/         - Список файлов
/api/v1/files/upload   - Загрузка файла


ВАЖНО:
------
⚠️ Сейчас используется in-memory хранилище (данные в памяти)
⚠️ При перезапуске backend все пользователи удалятся
⚠️ Это нормально для разработки и тестирования

Для production нужно:
1. Настроить PostgreSQL или другую БД
2. Использовать bcrypt для хеширования паролей
3. Настроить .env файл с секретными ключами
